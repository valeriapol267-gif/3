# Ассемблер УВМ — вариант 22

Практическая работа № 3. Реализованы этапы 1 и 2.

## Назначение

Программа переводит алгебраическую запись команд в список словарей
с полями A, B, C. Команды пока не выполняются.
На первом этапе бинарный файл не создаётся и не изменяется.
На втором этапе команды упаковываются в байты и записываются в файл.

## Запуск

Нужен Python 3.9+. Команды выполняются из корня проекта в PowerShell.
Используется Windows Python Launcher: py.
Приложению достаточно стандартной библиотеки; отдельная сборка не нужна.
Для установки инструмента проверки стиля:

```powershell
py -m pip install -r requirements.txt
```

Проверка примеров из спецификации:

```powershell
py src/main.py -i examples/spec.asm -o program.bin --stage 1 --test
```

Ожидаемый вывод:

```text
Команд разобрано: 4
A=5, B=241, C=997
A=2, B=416, C=603
A=7, B=277, C=783
A=17, B=387, C=153
```

Запуск через скрипт:

```powershell
.\run.bat -i examples/spec.asm -o program.bin --stage 1 --test
```

## Параметры

| Параметр | Назначение |
|---|---|
| -i, --input | Обязательный путь к исходному файлу UTF-8, допускается BOM. |
| -o, --output | Обязательный путь будущего бинарного файла. |
| --test | Этап 1: поля команд. Этап 2: машинные байты. |
| --stage | 1: внутреннее представление; 2: бинарный файл. По умолчанию 2. |
| -h, --help | Справка. |

Без --test этап 1 выводит количество команд, этап 2 — размер файла в байтах.
Относительные пути отсчитываются от текущей рабочей папки.
Папка результата должна существовать. Пути с пробелами берутся в кавычки.
Исходный файл и результат должны различаться.

## Алгебраический язык

M[x] обозначает значение памяти по адресу x.
M[M[x]] обозначает косвенное обращение: адрес берётся из ячейки M[x].
Одна команда записывается на одной строке.

| Форма команды | Код A | Поле B | Поле C |
|---|---|---|---|
| M[c] = b | 5 | Константа b. | Адрес результата c. |
| M[c] = M[M[b]] | 2 | Адрес ячейки с адресом источника b. | Адрес результата c. |
| M[M[b]] = M[c] | 7 | Адрес ячейки с адресом назначения b. | Адрес источника c. |
| M[M[c]] = sqrt(M[M[b]]) | 17 | Адрес указателя источника b. | Адрес указателя назначения c. |

Для sqrt вычисляется корень из значения M[M[b]], результат записывается
в M[M[c]]. На первых этапах эта операция только ассемблируется.

Адреса: 0..4194303, то есть 22 бита.
Константа загрузки: 0..1073741823, то есть 30 бит.
Числа беззнаковые: десятичные или шестнадцатеричные с префиксом 0x.
Регистр букв M и sqrt не важен. Между токенами разрешены пробелы и табуляция.
Пустые строки игнорируются. Комментарий начинается с # и идёт до конца строки.

Произвольные выражения, переменные, метки и переходы не поддерживаются.
Поддерживаются ровно четыре формы из таблицы.

Файл examples/spec.asm:

```text
M[997] = 241
M[603] = M[M[416]]
M[M[277]] = M[783]
M[M[153]] = sqrt(M[M[387]])
```

Пример с комментарием и шестнадцатеричными числами:

```text
m[0x3E5] = 0xF1 # записать 241 по адресу 997
```

Внутреннее представление первой команды:

```text
{'A': 5, 'B': 241, 'C': 997}
```

## Этап 2: создание и проверка бинарного файла

```powershell
py src/main.py -i examples/spec.asm -o program.bin --stage 2 --test
```

Ожидаемый результат:

```text
Размер двоичного файла: 29 байт
0x25, 0x1E, 0x00, 0x00, 0x28, 0x1F, 0x00, 0x00
0x02, 0x34, 0x00, 0xD8, 0x12, 0x00, 0x00
0xA7, 0x22, 0x00, 0x78, 0x18, 0x00, 0x00
0x71, 0x30, 0x00, 0xC8, 0x04, 0x00, 0x00
```

Проверка размера и содержимого реально записанного файла:

```powershell
(Get-Item .\program.bin).Length
Format-Hex -Path .\program.bin
```

Размер должен быть 29 байт: 8 + 7 + 7 + 7.
В файле нет заголовка, текстовых разделителей и переводов строк.
Format-Hex группирует байты по своим строкам, а не по командам УВМ.
В тестовом выводе ассемблера каждая строка соответствует одной команде.

Обычный запуск без тестового вывода, этап 2 выбран по умолчанию:

```powershell
.\run.bat -i examples/spec.asm -o program.bin
```

Ожидается только сообщение: Размер двоичного файла: 29 байт.

### Битовые поля

Поле A занимает биты 0–4. Байт с младшими битами записывается первым.

| Команда | A | B | C | Размер |
|---|---|---|---|---|
| Загрузка константы | 5 | биты 5–34 | биты 35–56 | 8 байт |
| Чтение памяти | 2 | биты 5–26 | биты 27–48 | 7 байт |
| Запись памяти | 7 | биты 5–26 | биты 27–48 | 7 байт |
| sqrt | 17 | биты 5–26 | биты 27–48 | 7 байт |

Загрузка константы: word = A | (B << 5) | (C << 35).
Остальные команды: word = A | (B << 5) | (C << 27).
Неиспользуемые старшие биты равны нулю.

Весь исходник разбирается и кодируется до открытия выходного файла на запись.
При ошибке исходной программы прежний бинарный файл не изменяется.
При успехе существующий результат заменяется.
Файл program.bin создаётся локально, но исключается из Git.

## Ошибки и тесты

Проверяются синтаксис, скобки, формы обращений к памяти и диапазоны полей.
Пустая программа считается ошибкой. Ошибка разбора содержит номер строки.
Ошибки исходника и файлов выводятся в stderr с кодом завершения 1.
Ошибки аргументов CLI дают код 2. Успех: код 0.

```powershell
$env:PYTHONPATH = "src"
py -m unittest discover -s tests -v
py -m flake8 --max-line-length=79 --max-complexity=10 src tests
```

Ожидается OK у тестов и отсутствие сообщений flake8.
Проверяются четыре примера полей и байтов из спецификации, разные длины
команд, общий размер файла, границы значений, синтаксис и CLI.
Полный набор содержит 18 тестов.

## Модули и функции

- src/spec.py: Field и Command описывают поля; check_value проверяет значения.
- src/parser.py: memory строит шаблон обращения к памяти.
- src/parser.py: parse_number читает число; parse_instruction разбирает команду.
- src/parser.py: parse_program разбирает файл; format_fields форматирует поля.
- src/machine.py: encode_instruction кодирует команду; encode_program собирает блоки.
- src/machine.py: format_bytes форматирует байтовый вывод.
- src/main.py: parse_args читает CLI; validate_paths проверяет пути.
- src/main.py: run выполняет этап; main обрабатывает ошибки.
- tests/: автоматические проверки.
- examples/: исходная программа из спецификации.
- run.bat: запуск через py.

Бинарные результаты, архивы, кэш Python, окружения и настройки IDE
исключены из Git. Коммиты оформляются по Conventional Commits.
